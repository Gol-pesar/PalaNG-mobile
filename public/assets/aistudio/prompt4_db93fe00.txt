MASTER PROMPT — Build a Native Android VPN Client Powered by Xray-core

You are a senior Android engineer, Kotlin architect, networking engineer, and VPN infrastructure developer.

Build a complete, high-performance native Android VPN client powered by the REAL Xray-core engine.

This is a production-oriented Android application, not a UI prototype, not a browser application, and not a simulated proxy client.

1. PROJECT OBJECTIVE

Create a native Android application that routes device traffic through remote proxy servers using Xray-core.

The application must support:

- VLESS
- VMess
- Trojan
- Shadowsocks
- HTTP Proxy
- SOCKS5 Proxy

The application must support three configuration import methods:

1. Direct proxy links.
2. QR code scanning.
3. Subscription URLs.

The primary operating mode must be a full-device VPN using Android VpnService and a TUN interface.

Application language: Persian (Farsi).
Layout direction: RTL.
Architecture: Native Android.
Programming language: Kotlin.
UI: Jetpack Compose and Material 3.

Do not use Python, Chaquopy, WebView, Flutter, React Native, or a web-based interface.

2. CRITICAL ENGINEERING REQUIREMENTS

Xray-core must be the actual networking engine.

Do not implement VLESS, VMess, Trojan, or Shadowsocks protocol handling manually.

Do not simulate successful connections.

Do not create fake speed measurements or fake connection states.

Do not use a placeholder engine and claim that the VPN works.

Google AI Studio Android builder does not support compiling Go, C/C++, or Android NDK code. Therefore:

- Generate the complete Kotlin application and Android integration layer.
- Create a well-defined native engine integration interface.
- Prepare the project to accept a real, externally built Xray Android AAR/JNI library.
- Do not invent the API of the native library.
- Document all required native functions and their expected signatures.
- Keep the project buildable without the native library, but show an explicit ENGINE_NOT_INSTALLED state.
- Never report CONNECTED unless the actual engine and VPN tunnel have successfully started.

The final native integration must use a real Xray-core Android build, based on the official upstream source and a verified compatible release.

Native Engine Layer

Create an interface named XrayEngineAdapter.

Its responsibilities:

- Initialize Xray-core.
- Load and validate an Xray JSON configuration.
- Start the engine.
- Stop the engine.
- Restart the engine.
- Report engine state.
- Retrieve traffic statistics.
- Report errors and diagnostic logs.
- Integrate with Android TUN.

Use the upstream Xray Android TUN integration mechanism when supported by the selected core version, including the documented TUN file descriptor mechanism. If the selected build requires a separate TUN-to-SOCKS bridge, implement a proper native bridge instead.

Do not assume that a generic gomobile library exposes methods it does not actually provide.

Keep the native API isolated behind XrayEngineAdapter so that the actual library can be integrated later without rewriting the UI or application architecture.

4. VPN IMPLEMENTATION

Create a real Android VPN service.

Requirements:

- Extend Android VpnService.
- Declare the service correctly in AndroidManifest.xml.
- Request VPN permission through VpnService.prepare().
- Establish a TUN interface.
- Support IPv4 and IPv6.
- Configure DNS servers.
- Support private DNS and configurable DNS strategies where technically possible.
- Prevent traffic leaks when the VPN is active.
- Handle Android VPN lifecycle events.
- Support connection cancellation.
- Release all file descriptors and resources correctly.
- Avoid duplicate VPN service instances.
- Support foreground service requirements for modern Android versions.

Do not route packets into a dead-end TUN interface.

Every accepted packet must have a valid forwarding path through the real Xray engine or a verified TUN bridge.

Avoid infinite routing loops by protecting the proxy engine's own upstream sockets using the Android VPN protection mechanism.
